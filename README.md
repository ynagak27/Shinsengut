# 新選組の軌跡 — The Road of Shinsengumi, the last group of Samurai

An interactive bilingual (JA/EN) map + timeline of the Shinsengumi — the corps,
the people in it and around it, and the era's national events running alongside —
with a story page and a people page of biographies.

The front page (`index.html`) asks what the visitor wants to do — find out who
they were, live through the key moments, follow one man's life, or explore the
map on their own — and sends them straight to the right place
(cards are in `js/home.js`). The map itself is `map.html`; old `index.html?ev=` /
`?person=` links are forwarded there, and `map.html?tour=1` starts the guided tour.

Self-hosted, no build step, no framework. Serve the folder from any static host
(GitHub Pages, Netlify, an S3 bucket, or just a local server).

The map itself is the real Google Maps JavaScript API (custom dark styling, not
the default look), so you'll need a Google Maps API key — see below.

---

## Google Maps API key

1. In the [Google Cloud Console](https://console.cloud.google.com/google/maps-apis),
   create (or pick) a project and enable the **Maps JavaScript API**.
2. Create an API key, then restrict it (Credentials → your key → Application
   restrictions → **Websites**) to the domain(s) you deploy to — e.g.
   `yourname.github.io/*` and `localhost:8000/*` for local testing. Maps
   JavaScript API keys are meant to live in client-side code; the website
   restriction is what keeps it from being used elsewhere.
3. Copy `js/config.example.js` to `js/config.js` and paste your key in:
   ```js
   const GOOGLE_MAPS_API_KEY = "your-key-here";
   ```
   `js/config.js` is gitignored, so your key never gets committed.
4. Billing must be enabled on the Cloud project (Google requires a linked
   billing account for the Maps JS API), but the free monthly credit covers
   normal personal-site traffic.

## Running it

Because it loads separate `data/*.js` files, most browsers won't run it from a
raw `file://` open — use a tiny local server:

```bash
cd shinsengumi
python3 -m http.server 8000
# then visit http://localhost:8000
```

To publish: push the whole folder to a GitHub repo and turn on Pages, or drag the
folder onto Netlify. That's the entire deploy.

## File layout

```
shinsengumi/
├── index.html        ← front page: three ways in (text in js/home.js)
├── map.html          ← the map page; shell only, you rarely touch this
├── basics.html       ← Shinsengumi basics, English only
├── story.html        ← 新選組とは: the corps' story (text in data/story.js)
├── people.html       ← 隊士: every member, and one biography per ?p=<id>
├── play/             ← 物語で体験する: key moments as a visual novel (text in data/play.js)
├── css/              ← style.css (shared), home.css, story.css, people.css, basics.css
├── js/               ← home.js (front page), app.js (map), story.js, people.js
├── oldmaps/          ← Edo-era map tiles (generated by tools/oldmaps/)
└── data/
    ├── people.js     ← the biographies  ← EDIT THESE
    ├── events.js     ← Shinsengumi events  ← EDIT THESE
    ├── context.js    ← national history & ishin shishi  ← EDIT THESE
    ├── story.js      ← the story page's text  ← EDIT THESE
    ├── play.js       ← the visual-novel chapters  ← EDIT THESE
    └── oldmaps.js    ← which period maps exist and their credits
```

**The whole point of the split: all content lives in `data/`.** As your reading of
the Shinsengumi books and documents turns up more, you add it there and never have
to understand the app code.

Every text field is bilingual: `{en:"...", ja:"..."}`. Leave one side blank while
drafting if you like — the app just shows the empty string.

## Adding to a person (`data/people.js`)

Each person is a keyed block. The two things you'll do most:

**Expand a biography** — add another section. Sections render in order, each with a
heading and body. Use `\n\n` for paragraph breaks inside a body.

```js
sections: [
  { h:{en:"Swordsmanship", ja:"剣術"},
    b:{en:"Long paragraph...\n\nSecond paragraph...",
       ja:"長い段落…\n\n第二段落…"} },
  // ...add as many as you like
]
```

**Flag lore vs. fact** — the optional `legend` field renders in a dashed red box,
kept visually separate from the documented narrative. Use it for anything from
Shiba Ryōtarō / Shimozawa Kan / later fiction that "everyone knows" but isn't in
primary sources.

```js
legend:{en:"The left-handed thrust is a novelist's invention...",
        ja:"左片手突きは小説家の創作で…"}
```

**Add a brand-new person** — copy any block, give it a new key (e.g. `itou:`),
then reference that key from any event's `people` / `roles`.

## Adding an event (`data/events.js`)

```js
{id:"unique_id", sort:"1864-07-08", year:"1864",
 story:true,                        // optional: a stop on the main guided tour
 coords:[35.0090,135.7701], zoom:15,
 date:{en:"July 8, 1864", ja:"1864年7月8日"},
 loc:{en:"...", ja:"..."},
 title:{en:"...", ja:"..."},
 desc:{en:"Full narrative...", ja:"物語…"},   // \n\n for paragraphs
 people:["kondo","okita","hijikata"],
 roles:{                            // what each person specifically did
   kondo:{en:"Led the assault party...", ja:"斬り込みを率い…"},
   okita:{en:"Fell mid-fight...", ja:"戦闘中に倒れ…"}
 },
 legend:{en:"...optional...", ja:"…任意…"}
}
```

- `sort` (YYYY-MM-DD) sets timeline order — approximate dates are fine.
- Every corps event gets a numbered pin, in `sort` order. Selecting a person dims
  the rest and draws a line through the events whose `people` list includes them.
- `story:true` marks the corps' main story: the stops of the guided tour
  (順路をたどる) when no one is selected. With a person selected, the tour walks
  that person's own events instead, birth to grave.
- `roles` is optional per person; add or deepen these as research fills in who did
  what. They show both on the event card and under that person's "appears in" list.

## Adding national history (`data/context.js`)

Same schema, minus `story`. These render as ◇ diamonds and toggle on/off with the
"Historical events / 時代の動き" button. They can still reference corps members
(e.g. Harada at Ueno, the corps receiving its name at the 8/18 coup) via
`people` / `roles`.

Use this file for the parallel track you wanted: what the shogunate and the
ishin shishi (Satsuma, Chōshū, Tosa loyalists — Ryōma, Katsura, Saigō...) were
doing at each moment.

## Experience the story (`play/`, text in `data/play.js`)

A third way into the history, after the map and the story page: key moments told
one tap at a time, as a visual novel over the period maps. It runs on
[Monogatari](https://github.com/Monogatari/Monogatari) 2.8.0 (MIT, the engine is
copied into `play/engine/`), restyled with this site's colours and fonts in
`play/style/play.css`. It is linked from the map header and the end of the story page.

**The rule for every chapter:**

- `kind:"record"` (史実) is what the record shows.
- `kind:"anecdote"` (逸話) is a well-known traditional story, used only where the
  record is silent. It shows in the same dashed red box as legends on the map.
- `kind:"context"` (解説) is narration that connects the beats around it (why
  something mattered, what it led to). It adds no new facts, so it has no `src`.
- Nothing is invented. A person speaks only words that are recorded or
  traditionally attributed to them. Every record and anecdote names its source in `src`.

**Adding a beat:** copy one in `data/play.js` and change `scene`, `kind`, `year`,
`ja`, `en` and `src`. Each beat is one tap.

**Adding a place:** add it to `PLAY.places`, then cut its background from the
period-map tiles:

```bash
python3 tools/play/crop.py edo-keio 16 35.6926 139.7333 play/assets/scenes/ichigaya.webp
```

Use `edo-keio` for Edo, `kyoto-genji` for Kyoto (add `--paper`, as the scan is
tilted and its edges would otherwise show dark), `ino-daizu` for Tama and
`ino-chuzu` for whole routes; see the examples at the top of the script. For a place none of the maps covers (Osaka, Tennōzan), set `map: "none"` and
`img: "unmapped"`: it shows plain paper and says so in the credit line. Set the
place's `map` to the map's id otherwise: the title screen lists the full credit for every map
in use, in the holder's wording from `data/oldmaps.js`.

**Adding a chapter:** add a block to `PLAY.chapters`. It appears on the title
screen's chapter list in that order, and is marked as read once finished.

**Chapters:** Shieikan, Mibu, Serizawa, Ikedaya, Kinmon, Yamanami, Aburanokōji,
Toba–Fushimi, Kōshū–Nagareyama–Itabashi, Utsunomiya and Aizu, Hakodate (with an
epilogue to 1915). All eleven are written.
Finishing a chapter records it in the browser (`shinsengumi.stamps`), ready for the
map to show later.

## Shinsengumi basics (English only)

`basics.html` is a short primer for English readers who don't know the
background: Japan in the 1860s, the two sides, the corps, who's who, a
timeline, a glossary and how to read names and dates. Japanese readers
usually know this, so it has no Japanese version and is linked only on the
English side: the map's welcome panel, the story page and the play page's
chapter list. Facts follow `data/events.js`, `context.js` and `people.js`.

---

## Verification note

Coordinates and dates were compiled from standard secondary sources as a research
starting point. Some are approximate historical sites (the Shieikan, Fudōdō
barracks) and a few dates are genuinely debated (Serizawa's assassination). Treat
this as a first draft to correct against your primary reading — that's exactly what
the `data/` split is for.
